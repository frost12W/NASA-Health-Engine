# Журнал решений

Зафиксированные технические решения проекта. Формат: контекст → решение → последствия.
Дата: 14.11.2026.

## Р-1. Пульс считается классическим методом, а не нейросетью

**Контекст.** Задача — пульс по видео лица. Есть два пути: классические rPPG-алгоритмы
(POS, Wang 2017; CHROM, de Haan 2013) и обученные модели (PhysNet, MTTS-CAN и подобные).

**Решение.** Основной и единственный рабочий метод — POS/CHROM с гейтами качества.

**Почему.**
- Нет обучающих данных: нужны пары «видео + эталонный ЭКГ/PPG» (UBFC, PURE, MMPD), доступ по заявке.
- Нет способа проверить модель на нашем железе: без валидации она выдаст число и на шуме.
- Классика объяснима: каждый шаг — фильтр, проекция, спектр — можно показать и защитить.
- Метод уже даёт валидный результат: 65.9 уд/мин, расхождение методов 0.16 (`docs/VALIDATION.md`).

**Последствия.** Модель не обучается, датасет не требуется для работы. При появлении
PURE/UBFC возможна валидация (MAE), затем — гибрид.

## Р-2. ML в проекте есть, но на этапе восприятия

**Контекст.** На вопрос «где ваша ML-часть» нужно отвечать фактами, а не обещаниями.

**Решение.** ML используется для поиска лица и 478 точек (MediaPipe Face Landmarker).
Измерение пульса — детерминированный DSP.

**Последствия.** В питче и документации так и формулируем: «ML — для восприятия,
классический метод — для измерения». Это не «без ML».

## Р-3. ML для оценки пульса — roadmap, не текущая итерация

**Контекст.** Менторы советуют использовать датасеты и ML.

**Решение.** В roadmap: валидация на PURE/UBFC → MAE → при достаточном качестве
гибридная схема (ML-денойзинг или модель поверх классики).

**Условия входа в работу:** получен хотя бы один датасет с эталоном; есть время
на обучение и проверку; метрика качества сравнима с текущей.

**Последствия.** Никаких заявлений «модель обучена». В `docs/PITCH.md` — готовый ответ
на вопрос про ML.

## Р-4. Цвет и «болезни по оттенку» — не реализуем

**Контекст.** Идея сравнивать RGB кадра с текстовыми описаниями болезней и их цветов.

**Решение.** Не реализуем. Максимум в будущем — наблюдение отклонения оттенка от личной
базы с калибровкой света, без называния болезни.

**Почему.** Абсолютные пороги RGB не работают: свет, баланс белого, тон кожи, зона съёмки.
Назвать болезнь по цвету — медицинское утверждение, которого проект не делает.

**Последствия.** Тема не попадает ни в код, ни в питч.

## Р-5. Формат кадра запрашиваем, но не заявляем

**Контекст.** YUY2 против MJPEG: сжатие действительно портит цветовую модуляцию.

**Решение.** Запрашиваем YUY2, читаем фактический формат из драйвера и показываем его.
Не утверждаем «несжатый», если драйвер отдал другое.

**Последствия.** В замере видно `YUY2, 640×480, 15.6 к/с` — это факт, а не обещание.
